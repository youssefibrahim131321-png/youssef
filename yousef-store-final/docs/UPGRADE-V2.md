# ترقية متجر يوسف — V2

## ما تم تطويره

أُعيدت صياغة الطبقة البصرية للصفحة الرئيسية بألوان متدرجة دافئة مع لون مساعد تركوازي، وبطاقات أكثر عمقًا، وحالات hover واضحة، وتحسينات للتخطيط على الشاشات الصغيرة، مع الحفاظ على الهوية العربية واتجاه RTL. أُضيفت أيضًا معالجة لحالة تقليل الحركة لتكون الواجهة ألطف على المستخدمين الذين يفضلون ذلك.

## إصلاحات الأمان والوظائف

تم إيقاف إعادة التوجيه المبني على Host غير موثوق عندما لا يكون `SITE_URL` أو `ALLOWED_HOSTS` مضبوطًا، وأصبح مسار لوحة الإدارة يرفض عرض الواجهة عند وجود `must_change_password`. تم تقليل كاش المستخدم في النسخة الواحدة إلى ثانية واحدة، وإضافة قفل محاولات 2FA مرتبطًا بـ `pendingToken` مع خمس محاولات كحد أقصى وقفل مؤقت لعشر دقائق، مع تأخير استهلاك توكن التحقق إلى ما بعد نجاح الكود.

تمت إضافة سقف افتراضي قدره ثلاثة طلبات Paymob معلقة لكل مستخدم ضمن نافذة زمنية قابلة للضبط، ومنع تكرار إنشاء عملية الدفع عبر `Idempotency-Key` أو بصمة تلقائية لمحتوى الطلب. كما أصبح غياب `PAYMOB_HMAC_SECRET` يظهر كتحذير صريح عند الإقلاع مع استمرار رفض الـ webhook بأمان.

## تحسينات الوصول والتحديث

أصبح درج السلة ومودال المنتج يحملان دلالات `dialog` و`aria-modal`، مع إغلاق عبر Escape، وحبس التركيز داخل النافذة، واستعادة التركيز للعنصر السابق. زر إزالة المنتج أصبح زرًا حقيقيًا قابلًا للوحة المفاتيح، وصور المنتج الأساسية لها أبعاد ثابتة لتقليل Layout Shift. تم تغيير استراتيجية كاش ملفات CSS وJavaScript إلى Network First مع إصدار Service Worker جديد، مع إبقاء HTML غير متكاش كما هو.

## الأتمتة

أُضيف الأمر `npm run automation:health`، وهو فحص تشغيلي قابل للتشغيل دوريًا من cron أو CI عبر `STORE_URL`. يفحص `/api/health` و`/api/config` ويعيد JSON ورمز خروج غير صفري عند فشل الخدمة. كما يستفيد النظام من مكنسة Paymob الحالية وسقف الطلبات المعلقة الجديد.

## التحقق

نجحت اختبارات المشروع كاملة: **94/94**، ونجح `npm run lint` و`npm run typecheck`. نجح فحص الأتمتة على النسخة المحلية المتاحة عبر المنفذ 4173 وأعاد `ok: true`.

## إعدادات مقترحة للإنتاج

| المتغير | القيمة المقترحة |
|---|---|
| `SITE_URL` | رابط المتجر HTTPS الحقيقي |
| `ALLOWED_HOSTS` | النطاق الحقيقي فقط، مفصولًا بفواصل |
| `MAX_PENDING_PAYMOB_ORDERS` | 2 أو 3 حسب سياسة المتجر |
| `PAYMOB_PENDING_WINDOW_MINUTES` | 45 أو أقل حسب دورة الدفع |
| `PAYMOB_HMAC_SECRET` | السر الحقيقي من Paymob |
| `DATA_DIR` و`UPLOADS_DIR` و`BACKUP_DIR` | Volumes دائمة خارج مجلد المشروع |
| `STORE_URL` | رابط الخدمة لتشغيل `npm run automation:health` |

## الجولة التصميمية الإضافية — V3

أُضيفت طبقة حركة وهوية بصرية جديدة فوق التصميم السابق. تشمل التغييرات توهجًا محيطيًا منخفض الشدة، تدرجات متحركة للعناوين والأزرار، لمعانًا تفاعليًا على صورة البطل، حالات hover أكثر وضوحًا للبطاقات، دورانًا طفيفًا لبطاقات الأقسام، ظهورًا متدرجًا مع blur خفيف لعناصر الأقسام، وحالة نشطة للروابط أثناء التمرير. تم ضبط كل هذه التأثيرات على الهاتف، وتعطيل أو تقليل الحركات تلقائيًا عند تفعيل `prefers-reduced-motion`.

تمت مراجعة النسخة بصريًا على الصفحة الرئيسية، ونجحت الاختبارات كاملة بعد التعديل: **94/94 اختبارًا، lint ناجح، typecheck ناجح**.

## الجولة الإصلاحية — V4

تمت إضافة رابط مباشر لتتبع الطلب من شاشة النجاح، وحفظ آخر طلب محليًا، وتحسين صفحة حالة الدفع بخطوات واضحة وزر تواصل. أضيفت شارات حالة المخزون والتوصيل والإرجاع إلى بطاقات المنتجات، مع أبعاد ثابتة للصور وتعطيل زر السلة للمنتج غير المتاح.

تم تحسين لوحة الطلبات بملخص سريع للنتائج وحفظ الفلاتر محليًا لاستعادة آخر بحث، مع تنفيذ الملخص بطريقة آمنة لا تمرر قيمًا غير مهربة إلى HTML. كما أضيفت metadata وصفحة حالة أكثر وضوحًا للمستخدم، وتحسينات responsive للموبايل.

التحقق النهائي: `npm test` نجح بعدد 94 اختبارًا، و`npm run lint` و`npm run typecheck` نجحا. التشغيل المحلي يتطلب `ALLOW_MEMORY_DB=1` للتطوير فقط إذا لم تتوفر PostgreSQL، ولا ينبغي استخدام ذلك في الإنتاج.

## عناصر لا ينبغي اعتبارها مشكلة

المشروع يحتوي بالفعل على مسارات `/robots.txt` و`/sitemap.xml` من الخادم، لذلك لم تتم إضافة نسخة ثابتة متكررة. كما أن صفحات الحساب والإدارة noindex عمدًا لأنها ليست صفحات تسويقية عامة.
